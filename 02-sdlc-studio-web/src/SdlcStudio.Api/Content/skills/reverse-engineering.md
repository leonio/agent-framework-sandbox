title: Reverse engineering a code base
description: How to infer requirements from code without over-reading it.
---
## Skill: reverse engineering
- Start from the outside in: README, build files, entry points, routes/controllers, then data models.
- Treat tests as executable requirements; they are the most reliable source of intent.
- Separate "what the code does" from "what it was probably meant to do" and label inferences.
